## 2. API 清单

| 模块 | 路由 | 说明 |
|---|---|---|
| dashboard | GET /api/dashboard | 各库文件数/体积、review_pending、today_new、最近任务、dup 可回收 |
| review | GET /api/review | 复核列表（可按库/状态过滤） |
| review | POST /api/review/{id}/decide | 单条裁定：批准/改分类/改名/打标签/忽略；批准且有 suggested_dst 时真实移动并写 operations |
| review | POST /api/review/decide-batch | 批量裁定 |
| jobs | POST /api/jobs | 发起整理（root 或 library，dry-run / use_llm / use_sem）；guard 校验后后台线程跑 cmd_plan，立即返回 running |
| jobs | GET /api/jobs / GET /api/jobs/{id} | 列表 / 详情（含 plan + items + plan_items_total） |
| jobs | POST /api/jobs/{plan_id}/apply | 确认执行（全部 move/rename 项） |
| jobs | POST /api/jobs/{plan_id}/rollback | 回滚（按 operations 映射表把文件移回原位） |
| browse | GET /api/browse | 分类树 / 按标签筛选 |
| browse | GET /api/browse/search | 文件名/正文搜索 |
| browse | GET /api/browse/file | 文件详情（含分类依据、tags、operations 历史） |
| rules | GET /api/rules | 三份规则 + 阈值 |
| rules | PUT /api/rules/{work,family,media} | 回写规则（先 DB.save_rules 版本化，再回写 JSON，写前备份 .bak） |
| settings | GET /api/settings | 库路径（禁改）、模型端点、阈值、定时任务、自动执行开关 |
| settings | PUT /api/settings | 只改 thresholds / auto_apply / schedule |
| settings | POST /api/settings/key | 写 config/.env.local（600）+ os.environ；GET 只返回掩码（如 sk****gh） |

页面路由：`/` `/review` `/jobs` `/browse` `/rules` `/settings`（Jinja2 模板渲染）。

## 6. 联调中发现并修复的问题（3 个）

1. **`common/db.py` 逗号丢失**（联调修复）：P1.1 加 auto_exempt 列时，INSERT 的 SQL 字符串后丢了逗号，
   Python 把字符串当函数调用，`TypeError: 'str' object is not callable`，5 个 API 测试报错。已补逗号。
2. **任务详情缺 `items` 键**（联调修复）：`GET /api/jobs/{id}` 只返回 `plan_items`，前端 jobs.html
   与测试都用 `data.items`。已在后端加 `items` 别名（`plan_items` 保留兼容）。
3. **五个子页面 404**（联调修复）：后端只注册了 `/` 页面路由，`/review` 等无路由。
   已在 `api/main.py` 补五条页面路由（模板存在时渲染，不存在时 404 提示）。

另：阈值保存路由已按前端 NOTES 的确认点落定为 `PUT /api/settings {thresholds}`，
前端 rules.html 已改（后端 rules 路由只接受 work/family/media）。

教训：测试夹具须用**真实规则**的关键词——P1 夹具的「供货合同」在真实
baijing-supply-v8 词表里不存在（词表是「产品销售合同」等长词组），裸词「合同」
不命中，第一次端到端测试因此全进复核、apply 移动 0 项。已改用真实关键词重做夹具。
