## 1. 改动一：LLM 调用链改为本地优先（王震 2026-11-20 08:59 亲定）

### 新链（三档，档内保持用户列表顺序）

1. 本地 Ollama（NAS 上的模型，按列表顺序）
2. 有免费额度的云模型（按用户在设置页排的顺序）

### 计费属性 billing

每个模型条目新增 `billing`：`free`（订阅/免费额度）或 `payg`（按量计费）。
类型默认值：ark-plan→free，ark-payg→payg，ollama→free（本地，强制，不可改），
custom→payg（除非用户在设置页显式标为 free）。
`common/llm_models.py` 的 `validate_models` 会把缺失的 billing 按类型默认值补齐，
填错的值直接拒绝（ValueError）；ollama 条目即使写 payg 也会被强制改回 free。

## 2. 改动二：PDF OCR 核实并加固

### 核实结论（线上容器内实测，部署前基线）

- `extract_text` 对 PDF 先读文字层，无文字层时调 `ocr_file`（POST 到 ocr-service /ocr），
  来源标记 `pdf-ocr`；图片走 `img-ocr`。**OCR 确实在用。**
- 容器环境变量 `OCR_URL=http://172.17.0.1:8866`（网关地址，实测 200）；
  容器内 `127.0.0.1:8866` 不通（Connection refused）。
- 真实扫描版 PDF 基线：`/vol1/1000/家庭文件/王子婴/王子婴出生证.pdf`
  （1.39MB，第 1 页 pdftotext 0 字符）——默认地址（127.0.0.1）返回来源 `scanned`、
  文本长度 0（OCR 悄悄失效）；网关地址返回来源 `pdf-ocr`、文本长度 853。
  （早先误判的 `/vol1/1000/家庭文件/刘音/考试/肾内科1.pdf` 实际有文字层
  655 字符，不是扫描件——当时是路径写错导致 pdftotext 报错。）
- OCR 测试只报来源与长度，不打印识别出的个人文本内容。

### 加固改动

1. **默认地址自动探测**（`curator_core/textkit.py` 新增 `resolve_ocr_url()`）：
   环境变量 `OCR_URL` 优先；否则依次探测 127.0.0.1:8866 与网关 172.17.0.1:8866，
   GET /ocr 任意 HTTP 状态（含 405，只接受 POST）即算可达；两边都不通时默认网关地址
   （容器内正确地址）。结果按进程缓存。
2. **默认 OCR URL 改掉**：`api/deps.py` 的 `DEFAULT_OCR_URL` 由
   `http://127.0.0.1:8866` 改为 `http://172.17.0.1:8866`（容器内可达的宿主网关地址）；
   `curator_core/engine.py` 三处 `ocr_url="http://127.0.0.1:8866"` 默认值改为 `None`
   （由 textkit 探测）；`curator.py` 的 `--ocr-url` 默认值改为 `None`；
   `api/jobs.py` 的回退值改为 `None`。显式配置（libraries.json / 环境变量 /
   命令行）仍优先于默认值。
3. **设置页/向导页显示 OCR 端点可达状态**：`api/deps.py` 新增 `probe_ocr()`，
   `public_settings()` 附带 `ocr_status`（GET /api/setup 也返回同一份）；
   设置页「模型端点」下与向导页 OCR 输入框下各加一行状态
   （可达时显示 HTTP 状态与耗时，不可达时显示错误类型；探活超时 1.5 秒，不阻塞返回）。

### 已知限制（不修，只记录）

**Docling 中文 OCR 的数字会系统性误读为 0**（2026-11-15 归档实测结论）。
OCR 文本只用于判类/检索，绝不可信赖其中的数字（如金额、日期、编号）；
不要试图“修”这个误读——这是上游模型行为，不是本层 bug。
已写进本报告、`curator_core/textkit.py` 的 `ocr_file` docstring
与 `fpk/manifest` 的 changelog。

### 改动文件

| 文件 | 改动 |
|---|---|
| `curator_core/textkit.py` | `resolve_ocr_url()`、`LOCAL_OCR_URL`、`GATEWAY_OCR_URL`；`ocr_file`/`extract_text` 的 `ocr_url` 默认改为 `None`（自动探测）；`ocr_file` docstring 记数字误读限制 |
| `curator_core/engine.py` | 三处 `ocr_url` 默认值 `http://127.0.0.1:8866` → `None`（plan_files / explain / learn_rules） |
| `curator.py` | `--ocr-url` 默认值 → `None` |
| `api/jobs.py` | `ocr_url` 回退值 → `None` |
| `api/deps.py` | `DEFAULT_OCR_URL` → 网关地址；新增 `probe_ocr()`；`public_settings()` 附带 `ocr_status` |
| `web/templates/settings.html` | OCR 状态行（`#ocr-line`） |
| `web/templates/setup.html` | OCR 状态行（`#w-ocr-status`） |

### 回归测试（新增 `tests/test_textkit_ocr.py`，6 个）

- 环境变量优先；127.0.0.1 拒绝、网关 GET /ocr 返回 405 → 选网关地址；
  两边都不通 → 默认网关地址，不抛错
- OCR 服务不通时 `ocr_file` 返回空文本，不抛错
- 无文字层最小 PDF + OCR 不通 → 文本空、来源 `scanned`（不误标 pdf）
- 纯文本文件不受 OCR 影响
