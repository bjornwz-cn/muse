# P11-REPORT-2026-11-21：NAS Curator v0.1.8 —— 视频抽帧改走 cv2.VideoCapture，彻底去掉 ffmpeg 依赖

- 版本：0.1.7 → 0.1.8（commit `6ad4f69`，远程 HEAD 已核实）
- 日期：2026-11-21
- 背景：2026-11-21 13:53 王震问 NAS 整理 3000+ 待确认识别率低的原因；调查证实复核队列已达 33,479 条，其中计划 #107（媒体批）的 31,493 条里 12,696 条是视频 `decode_failed:ValueError`；根因是容器镜像自始未装 ffmpeg/sudo，视频抽帧的子进程调用必然失败。2026-11-21 14:32 王震点选方案 B（改用 cv2.VideoCapture）。

## 1. 根因（已三重验证，不复述分析过程）

- `media_core/curate.py` 的 `video_frame`/`_video_frame_at` 用 subprocess 调 `['sudo','-n','ffmpeg',...]` 抽帧；Dockerfile apt 清单只有 poppler-utils、catdoc、ca-certificates、curl，ffmpeg 和 sudo 都没装（0.1.0 与 0.1.7 镜像都缺）；抽不到帧 → `decode_item_frames` 抛 `ValueError('noframe')` → engine 按 decode_failed 进复核。
- 12,696 条里 12,619 条是视频（.mov 6,887、.mp4 3,695、.avi 1,294、.wmv 469、.mts 144、.rmvb 63、.flv 37、.vob 21、.3gp 5、.mpg 4），另 77 条是 <8px 的微小图片（.gif 59、.png 14、.jpg 4，走 `ValueError('tiny')`，与视频无关，重跑后仍会失败——见 §6）。
- 420 个.livp 全是 `decode_failed:UnidentifiedImageError`（PIL 打不开 zip 包），与 ffmpeg 无关，见 §2 的解包处理。
- 计划 #107：70,916 项（move 39,423、review 31,493），library=media，rules_version=None，status=pending_review，2026-11-20T15:59:56 生成。

## 2. 改动

### 2.1 `media_core/curate.py`（核心）

- 新增 `_load_cv2()`：延迟加载 cv2（模块 import 时绝不加载 cv2/torch；失败返回 None；先试直接 import，再试 `ensure_cv2_first()`）。cv2 缺失时视频抽帧返回空，由调用方按 decode_failed 处理——与旧版 ffmpeg 缺失时的行为一致。
- 新增 `_cap_frame(cv2, cap, ss)`：同一 VideoCapture 上逐点 seek 取帧；cv2 读到的是 BGR 帧，转 RGB 后包 PIL 返回，与旧 ffmpeg 管道的 mjpeg 解码结果一致（下游 `_image_features` / `classifier.scores` 均按 RGB 处理）。seek 到关键帧后向前解码；超片长的时间点读不到，直接跳过，**不回退到 0 秒**（旧 `_video_frame_at` 在多帧采样里若回退会造成首帧重复计票）。
- `video_frame(path, ss)`：改走 cv2，单帧 + 失败回退 ss='0' 的语义不变（仍返回 None 时由调用方处理）。
- `_video_frame_at(path, ss)`：改走 cv2，单次抽帧无回退（供 `video_frames()` 用）。
- `video_frames(path, max_frames=6, step=10)`：改走 cv2，**同一 VideoCapture 只开一次、逐点 seek**（旧版每点拉起一次 ffmpeg 子进程）；采样点与接口不变（0/10/20/30/40/50 秒、最多 6 帧）；全部时间点抽不到返回 `[]`。
- 新增 `_decode_livp_frames(path)`：.livp 是 zip 包（内含.jpg 静帧 +.mov），解包到临时目录后优先用其中的.mov 走 cv2 抽帧，.mov 不可用则用.jpg 静帧当一帧（.heic 静帧需 pillow_heif，已在模块 import 时注册，无则跳过）；临时目录用后删除；两种都不可用返回 `[]`。
- `decode_item_frames()`：`.livp` 先走 `_decode_livp_frames`（旧版当照片直接 PIL 打开，必然报 UnidentifiedImageError）；其余照片/视频路径不变，`ValueError('noframe')` 等备注口径不变。
- `import shutil`（解包复制用）。全仓 `grep ffmpeg --include="*.py"`：只剩本改动的注释说明，**无任何 ffmpeg 子进程调用残留**。
