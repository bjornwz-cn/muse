## 5. 遗留问题与已知局限（按优先级）

1. **SigLIP 缓存缺 `config.json`**（环境缺陷，非 P1 引入）：NAS 模型缓存
   `models--timm--ViT-B-16-SigLIP` 快照缺 `config.json`，且 `huggingface.co` 从 NAS
   不可达（000；但 example.com 200，说明只是 HF 被拦）。原版 `Classifier` 同环境实测
   同样失败（`open_clip.get_tokenizer` → `AutoTokenizer` → 缺 `config.json`）。
   P1 已做代码层兜底：`Classifier` 先走原版调用，失败时从本地快照目录直接建同款
   `HFTokenizer`（同一 `tokenizer.json`；另补上下文长度 64 而非默认 77，否则推理时
   `positional_embedding` 77 vs 64 报错）。媒体抽样已凭此跑通。
   根治办法：从可达处取回 `config.json` 放进该快照目录（或恢复完整缓存），需王震/母本定夺；
   P1 未动 NAS 任何文件，未自行补缓存。
2. **cv2 须 `LD_LIBRARY_PATH`**：marvis python 的 cv2 自身也要 libopenblasp，
   `.libs` 不在默认 so 搜索路径。`ensure_cv2_first` 已加 ctypes 按显式路径预加载兜底；
   但最稳仍是启动时带 `LD_LIBRARY_PATH=<site-packages>/opencv_python_headless.libs:
   .../opencv_contrib_python.libs:.../torch/lib`。P3 打包时须把这点写进启动脚本。
3. **CLI plan 未接媒体模型**：`plan` 的媒体分支 `classifier=None`，452 项 `no_classifier`。
   需 P1.1/P2 加 `--media-model`（或 mixed/media 自动建 `Classifier`）。
4. **`.mts` 扩展名碰撞**：146 个 node_modules `.d.mts`（TypeScript）被当视频抽帧失败。
   建议 P1.1：在媒体收集层按文件头/可读文本排除 `.d.mts`（或解码失败且内容为纯文本时记 `not-media`）。

## 6. 与 v3.1.1 的差异点（判定逻辑未改）

- `cmd_*` 的打印输出改为返回值（stats/report），不再写 CSV/JSON/报告文件（调用方持久化）。
- `apply_plan`：action=review/skip/tag 的项一律不移动（原 `cmd_apply` 默认连 99- 项也搬走，
  除非 `--keep-review`）；`keep_review=True` 时连 99- 类目的 move 项也保留。
- `plan_files` 新增可选参数（均为原 CLI 已有默认值）+ `db_conn`（跨轮去重）+ `dst_root`（归位）。
- 实体画像无独立步骤（与原版一致，只在 `semkit.classify` 内部及 prescreen 路径）。
- 媒体：视频由单帧（ss=2）改为多帧采样 + 众数投票；`write_report` 不落盘（只返文本）；
  `review_plan` 不写 TSV、不移动（`apply=True` 即抛错）；plan 与 apply 分离。
- 敏感隔离与 SHA256 精确重复进复核是原版 SKILL.md 承诺但代码缺失的逻辑，本次补齐
  （敏感词只匹配文件名 + 正文 `密码/身份证/护照/银行卡`；`key` 只匹配独立词）。
- llmkit：`CONFIG_PATH` 不再默认读同级 `llm.json`，只读环境变量或 `CURATOR_LLM_CONFIG` 指定文件。
