## 3. 复核队列批准 / 拒绝语义（查清的结论）

**查代码核实（0.1.1 现行逻辑）：** `api/review.py decide_one` —— rejected 只改状态；approved 若 payload 有 `suggested_dst` 且源文件存在则用 `apply_plan` 单条移动，否则只改状态；**绝不删除文件**。plan 产生的 review 项 dst 为空（`_to_plan_item` 里 is_review → dst=""），所以这类项批准后不移动；下拉传的 category 只作 apply item 的元数据，**不重新计算 dst**——下拉当时对目的地不起作用。**dup 批准在 0.1.1 里也不是删除（只改状态）**，不存在「批准即删」的逻辑；全仓 grep：复核流程里没有任何删除文件的逻辑，仅 media_core 删临时文件与 rollback.py 的 os.rmdir。

**0.1.2 的新行为：**

| 类别 | 批准（approved） | 拒绝（rejected） |
|---|---|---|
| **dup** | **移到 06-重复待确认 holding 区，不删除**。holding 路径按源文件所在顶层：工作→`工作文件/99-待确认/06-重复待确认/`；家庭→`家庭文件/<人>/99-待确认/06-重复待确认/`（保持人优先结构，人取自源路径，无则待分人）；媒体→`媒体库/99-待确认/06-重复待确认/`；笔记本备份→备份树内同名 holding 目录（`/vol1/1000/下载/Wangzhen-Mac/99-待确认/06-重复待确认/`，文件仍在备份树内、只是隔离）；收件箱/未知来源→收件箱 holding。下拉改顶层不生效（holding 按源顶层定）。源文件不存在则只改状态；已在目标位置时返回「已在目标位置，无需移动」。移动走 `_execute_move`：apply_plan 单条移动 + 写 operations + plan_item 置 done | 原地不动，只改状态 |
| **low_conf** | 有 `suggested_dst` 则只换库根（相对路径保留）；无则按新顶层默认一级目录（工作→归档/，家庭→`<人>/`，媒体→照片/视频按扩展名）；下拉未改则沿用原建议。源文件不存在或无建议时只改状态，不移动 | 只改状态 |
| **blur / ambiguous / sensitive** | 与 low_conf 同（只改状态或按建议移动，不删除） | 只改状态 |
